description: "Set up atlasmd for this project: write atlasmd.toml, make docs/start/, and give every code folder its README and its entry in atlasmd.toml"
---

Set up atlasmd for this project in four steps. Ask the person once, at step 2. Do the other steps without a question.

1. Run `"${CLAUDE_PLUGIN_ROOT}/bin/amd" scan --json`. It lists every Markdown file with its size, the folders that hold source files and a README (`candidates`), the folders that hold source files and no README (`without_readme`), and whether `atlasmd.toml` and `docs/start/` exist. Then read `CLAUDE.md` of the project if it exists, and the README at the root. Do not read every Markdown file.

2. Propose the setup to the person in one message, as three lists, and ask for a yes or corrections:
   - The `[[area]]` entries of `atlasmd.toml`: one for each folder that holds code, with a README or without one, so that every source file of the project is under the paths of an entry. Give each a name in plain words, its `paths`, and its `pack`: the files that Claude must read before it changes a file in those paths. A `pack` holds the README beside the code, the plans that name the folder, and the decisions that the code depends on. For a folder without a README, say that you will write `<folder>/README.md` from its files. Keep each `pack` under about 60,000 tokens, and give the estimate.
   - The four files of `docs/start/`, which Claude gets at the start of every session, and what from the files of the project goes into each. `10-map.md` gets what the project is and where each kind of fact lives. `20-open-items.md` gets the state of the work, one line for each item. `30-state.md` gets where things stand now. `40-way-of-work.md` gets the rules that every session needs. Keep the four files under 30,000 tokens in all.
   - The moves: which Markdown files move into `docs/decisions/` (one file per decision), `docs/plans/`, `docs/notes/` and `docs/archive/`, and which files get a new name. The rules: the folder says when a file is read. The name gives the order, the date or the number, and then the subject, in lower case with hyphens.

3. After the yes, write the `[[area]]` entries as a JSON list of `{name, paths, pack}` to a file in your scratchpad, and run `"${CLAUDE_PLUGIN_ROOT}/bin/amd" init --areas-json <that file>`. It writes `atlasmd.toml`, the four template files and the folders, and overwrites nothing. Then write the README.md of each code folder that has none, from the files of the folder: what the folder holds, how to run it, and its state, with the date. Then fill the four files of `docs/start/` from what you read. Use `git mv` for every move and rename, and update every link that a move breaks. Add this text to `CLAUDE.md`, or make the file with it: `atlasmd gives Claude the Markdown files in docs/start/ at the start of every session. Before you change a file in a folder that atlasmd.toml lists, read the files listed under pack for that folder. The hook refuses the edit until you read them.` Remove from `CLAUDE.md` any list of files to read at the start, because the files of `docs/start/` replace it.

4. Run `"${CLAUDE_PLUGIN_ROOT}/bin/amd" map`, then `"${CLAUDE_PLUGIN_ROOT}/bin/amd" check`. Fix what the check reports. Then tell the person: the tokens of the files in `docs/start/` against `start.budget`, each `[[area]]` with the tokens of its `pack`, the READMEs that you wrote, the files that you moved and renamed, and what you left for the person. Commit nothing unless the person asked for a commit.
